# T01 MCP transport qualification

The selected seam uses rmcp 3.5.1 for protocol dispatch and a separate Axum legacy
SSE adapter. `cargo xtask check T01` runs real client/server tests without Python,
providers, Valkey, deployment, or OAuth authorization. The qualification binary is
synthetic application wiring; production domain handlers remain T06 work.

## Transport and authentication decisions

Stdio runs a real child process. Streamable HTTP uses explicit rmcp client/server
features, supports JSON and incremental SSE responses, and defaults to stateless
JSON for the source configuration. Stateful HTTP is also exercised to verify
session identity and explicit DELETE cleanup. Legacy GET `/sse` plus POST message
routes use a dedicated shim; rmcp's `client-side-sse` feature is not that protocol.
GET/HEAD, custom message prefixes, accepted POST suffixes, invalid session IDs,
content types, malformed envelopes, 405 responses, expiry and 4 MiB limits have
executable coverage. Bearer HTTP rejects missing/wrong credentials with the
captured 401 contract. Legacy SSE has the source's unauthenticated behavior;
stdio inherits process trust. OAuth server/client implementation remains T04/T05.

## Fidelity boundary

The typed SDK's serde_json Value rounds the captured integer
18446744073709551617. This failing capability is retained as a characterization,
not accepted as fidelity. The selected gateway preserves raw JSON envelopes and
catalog schema/metadata using RawValue. Actual HTTP, stdio, legacy SSE and native
gateway tests retain this integer and an ordinary `$serde_json::private::Number`
object. `arbitrary_precision` is deliberately absent. Complete captured public
catalog descriptors also traverse the typed SDK, but this establishes descriptor
compatibility, not implementation of those production tools.

Opaque replies replace SDK output only after successful typed shape validation.
Request IDs remain raw integer/string identities; adjacent integers beyond u64
are tested through subprocess, HTTP and legacy SSE initialize/list/call replies.
Large IDs receive private SDK string aliases,
with original IDs retained for replies and upstream cancellation. Frames are
bounded during reads, not after an unbounded newline allocation. Pending requests
are limited to 32. HTTP retains aliases only for server-issued sessions; a
128-permit admission limit and invalid-session flood regression protect the table.
Canceled or rejected HTTP requests release alias leases. Stateful upstream
cancellation is delivered before its HTTP future is dropped, retaining the alias
until the original-ID notification has been correlated. Admission commits only
after all fallible raw rewriting, with malformed call-shape recovery tested.
Discovery uses names for tools/prompts, URIs for resources, and URI templates for
resource templates. Distinct resources may share display names. Discovery shares a 16 MiB byte budget across all catalogs/pages, in addition to
4 MiB per upstream RPC response. The typed client bounds JSON/error consumption
before buffering, rejects oversized Content-Length, and admits incremental POST
SSE bytes before the pinned parser. Standalone GET/resume uses the SDK event
limit. Discovery rejects duplicate identities, repeated cursors, more than
128 pages or 4096 items; readiness, discovery and request transports have bounded
deadlines. Negotiated upstream protocol versions govern every subsequent HTTP
header, including notifications, discovery, forwarded calls and DELETE. Both the
selected raw gateway and typed SDK probe explicitly propagate cancellation for
tools, resource reads and prompt retrieval.

Stateful qualification has a single 300-second idle owner. The SDK's independent
worker idle timer is disabled because it also counts time during active work.
Request and SSE body leases suspend idle expiry. Actual SDK termination is also
observed; idle close removes SDK sessions before releasing aliases/permits, and a
close timeout retains admission for retry. Rejected DELETE requests retain the
live SDK session, aliases and permit; a 128-session rejection regression verifies
that they cannot bypass admission. Explicit Host shutdown joins bounded
cleanup and reports drain failures. Router or abrupt Host drop signals the same
bounded drain, whose completion is separately observed and verified against SDK
sessions, aliases and permits. Tests inject a 100ms idle interval and prove a
400ms operation and live SSE survive, then expire after becoming idle.

The injected fixture handler deliberately restricts `payload.items` to integer
number tokens and has synthetic wait/error behaviors. These are test protocols,
not a complete JSON Schema validator or parity claim for Python tool validation;
for example integral floating/exponent forms are outside that fixture rule.
Captured positive Python echoes include integers above u64 and below i64. Raw
qualification framing supplies safe SDK placeholders for these integer tokens and
restores the captured-format payload only after successful handler execution.
Boolean, fractional, malformed-number and handler-failure negatives verify that
opaque restoration does not turn validation failures into successful replies.
Production tool behavior remains T06.

## Source observations and lifecycle

`fixtures/python-sse.json` records actual Python 3.14.7, FastMCP 4.0.11 and MCP
2.3.0 observations from pinned source 7b2d876307189d7a62000d1f289b3ef4b65eaff6.
The developer-only `export_mcp.py` reuses accepted F04 environment sanitization,
source pin verification and loopback-only network guards with injected fixture
state. Runtime and native CI gates consume captured data, never invoke Python.
The fixture includes exporter/helper/source/lock provenance. A Python 3.12.11
capture matched earlier transport observations; authoritative expanded lifecycle
observations use 3.14.7. No broader cross-version claim is made.

Actual source returns 405 for unsupported SSE methods and enforces a body limit;
earlier F01 inferred unrestricted method behavior is corrected by this evidence.
Source accepts requests after the initialize response before the advisory
initialized notification, rejects known calls before initialize, rejects malformed
initialize parameters, falls back on unsupported requested versions, and accepts
repeated initialization. The shared stdio/SSE framing adapter preserves these
captured phase outcomes while using the SDK dispatcher internally. SDK lifecycle
behavior alone is not treated as source parity.

## Acceptance evidence and remaining owners

Tests compare full nested schemas/defaults/nullable/metadata and reject mutations;
exercise actual errors, prompts/resources, injected state, disconnect/cancellation,
session cleanup, malformed/over-limit discovery and unsupported remote versions.
The raw gateway validates initialize protocol versions and response correlation,
handles incremental SSE data events, and forwards cancellation notifications with
original request IDs. Native evidence is source-bound by xtask and retained in CI
on both Linux architectures. Mandatory acceptance names must be present and non-ignored. Local tests do not establish production routing,
OAuth correctness, provider availability or cross-architecture CI outcomes.


Legacy SSE additionally admits 128 connections globally, returning 503 before
session allocations on saturation. One shared owned permit spans pump and stream
cleanup, including malformed handshake followed by disconnect, expiry and host
shutdown. These explicit native resource limits are documented intentional
admission choices in ADR 005, rather than inferred Python parity. The additive
`sse-stream =0.2.6` parser pin was already transitive in the accepted lockfile;
Cargo.lock adds only its direct ssx-mcp edge. F02's historical candidate pins remain
unchanged, with the T01-qualified dependency recorded separately.


All four catalogs, including paginated resource templates, share discovery limits
in both typed and raw gateway paths. Tools/prompts use name identity, resources
use URI and templates use `uriTemplate`; the typed local handler and raw subprocess
both republish the complete collected templates. The typed aggregate budget counts
canonical serialized retained entries and pagination cursors before retaining or forwarding
them; cursor escaping counts toward the same shared budget. The raw budget counts received catalog
envelopes before parsing. These are explicit retention/admission bounds, not a
throughput quota or a claim of identical threshold behavior for every encoding.

The native gate independently pins the full captured fixture to Git object
`75829eb63be037686f7016be542f9f4138878f82`, outside its own mutable metadata.
A fresh locked Python 3.14.7 capture reproduced the existing file byte for byte;
the parent independently recorded SHA256
`a28d432b17cc8fae505c42b145f82c44c16439bde105381270e2c9775351ab90` before
this pin was added. The mutation test changes a descriptor while retaining all
oracle/source/version provenance and requires the native digest validator to fail.
Legitimate fixture changes require renewed source capture and explicit pin review.

Raw gateway DELETE keeps the session identity after HTTP errors, connection
failures, or its bounded request deadline, allowing explicit retry. Successful
DELETE and already absent (404) clear only the attempted identity generation;
a concurrent completion cannot clear a replacement. As in rmcp, 405 means
unsupported termination and returns without a cleanup error; it does not prove
remote closure, so identity remains available for retry.

A real HTTP delayed-header regression also covers POST racing DELETE: headers
from a request sent under a closed or replaced session cannot restore its old
identity. The observed defect caused redundant later cleanup requests; no
remote-session leak was demonstrated. Initialization still establishes identity,
and a response arriving after failed DELETE retains the active generation.

The streamable HTTP response bridge scans each incoming SSE byte once with an
incremental ring buffer. Mixed LF/CRLF frame boundaries are consumed in arrival
order. Fragmentation cannot rescan the accumulated frame, and draining short
frames does not shift all remaining bytes. The existing 4 MiB buffered-response
limit and incomplete-frame rejection remain; mandatory tests count inspected
bytes for a bytewise near-limit frame and exercise mixed boundaries. Transport
chunks may coalesce a near-limit event and following events; the bridge retains
the remaining upstream Bytes and admits bounded slices between frame extractions.
The 4 MiB limit applies to each standalone event, including its delimiter.

The HTTP client's streamed response check bounds admitted wire bytes and its own
accumulation buffer. `reqwest::Response::chunk` returns an SDK-owned Bytes chunk
before that check, so this is not a peak RSS or upstream allocation guarantee.
The bridge likewise retains the current upstream chunk while consuming bounded
slices. SDK and HTTP body chunk allocation remain outside these admission bounds.

Transport sessions are connection-local routing state, not durable workflow
records. The pinned Python MCP SSE transport likewise stores active stream
writers and session owners in process-local maps. Both implementations require
requests for a live session to reach its owning process; neither survives a
process restart or promises transparent cross-replica session failover. Native
packaging and rollout must document and verify connection/session affinity (or
an explicitly reviewed replacement transport design). Valkey remains the sole
shared authority for durable application records, claims and budgets; these
transport maps do not substitute for it.


### Aggregate legacy admission correction

Legacy POST routes admit at most 32 messages globally, before the String body
extractor polls any body frame. Admission is nonblocking; saturation returns 503.
Each body remains limited to 4 MiB (at most 128 MiB of raw admitted input), and
`try_send` never parks additional body-owning sender futures. The message owns its
permit through queue and pump processing. Requests retain that permit through the
correlated SDK response entering the output queue, so full request and synthetic
reply copies retained by the opaque adapter are also limited to 32 globally.
Notifications release it after pump consumption. Invalid bodies, closed channels,
canceled body reads, session termination and pump failure release their owners.
Body extraction selects against host cancellation; shutdown reclaims admission
even while the peer keeps an incomplete request body open. Canceled hosts reject
new POST and SSE admission before buffering or session allocation.
Non-saturated 400/404/202 behavior and 128 session admission remain unchanged.
A canceled SDK call with no reply retains its pending transport ownership until
session teardown; no premature capacity release claims handler termination.

Output uses a separate shared 64 MiB byte admission budget. Each persistent reader
charges bytes before appending to its frame accumulator, with a 16 MiB frame
limit. Its fixed uncharged read scratch is 8 KiB per session (1 MiB across 128).
A partial read survives `select!` cancellation with its leases intact. Output
saturation, invalid UTF-8, incomplete frames and frame overflow close the session
without emitting a truncated response. Completed SSE frames reserve their exact
encoded byte count before allocation. Their byte owners survive channel dequeue,
HTTP body yield and Bytes cloning until the final consumer drops them. Raw-frame
leases remain held while rewriting and allocating the separately charged event.
Endpoint events use the same byte budget. There are no uncharged pending output
senders: blocked event sends retain their byte owner.

These are retained wire-byte admission budgets, not a process RSS limit. Vec
capacity, typed JSON object overhead, temporary validation/rewriting copies and
SDK handler allocations are additional. The ingress count also bounds concurrent
synthetic amplification and opaque pending state; a near-4-MiB echo regression
checks both complete text and structured output above the ingress size. The
16 MiB output frame ceiling explicitly rejects larger responses. Production
handler response-memory qualification remains T06/G03. The portal has no runtime
integration with this synthetic native MCP shim, so its browser contract is
unchanged; native transport tests are the applicable gate.
