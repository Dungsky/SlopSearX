# Portal impact review

These adapters affect browser-visible result identities, order, display dates,
omissions and structured payloads. A08 adds factories to the native registry;
it does not change the HTTP/MCP/portal request schema, capability declarations,
filter-enforcement policy or selection grants. All four remain text-only,
unsupported for audited filters, with no media; FRED requires auth/freemium and
the other three remain public/free. Provider dates are display metadata and
never become a filter-enforcement claim.

Actual native parsers execute captured original FDA and Oyez omission regressions
before accepted ranking and compact JSON projection. Oyez's two validated URLs
remain distinct, and unresolved FDA labels cannot create an empty-URL result.
Actual FDA payload/provenance remains canonical while compact cards apply the
existing 512-byte disclosure and 300-character snippet bounds. EDGAR's real
factory-loopback preserves two distinct filing URLs, company fallback,
contiguous retained positions and exact unresolved diagnostics. FRED's source
replays retain the full 600-character payload notes with a 200-character display
prefix. Exact source outputs, rather than generic engine scaffolds, feed these
checks.

The original Oyez regression also calls the Python HTML formatter; the source
capture retains that test's successful execution, but A08 does not claim a native
HTML/browser successor. T03/G01 must execute these exact native adapter results
through the actual portal renderer/browser and verify URL links, ordering,
omissions, dates and payload disclosure. T02/T06/G01 must test the full HTTP/MCP
routes and canonical snapshot/read-result boundary. Compact projection is not
an HTML renderer or transport proof. The two fake-engine biomedical profile
nodes in `test_misc_polish.py` are recorded G01 handoffs, not proof of FDA adapter
implementation. Existing Python portal CI gates remain active.
