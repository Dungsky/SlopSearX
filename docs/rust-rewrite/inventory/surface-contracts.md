## HTTP API and portal

The public FastAPI app is `slopsearx.server:app`; its lifespan builds shared engines/services and tears them down. `/` and `/search` are aliases, each accepts GET query parameters and POST form-encoded fields, and both pass through the same service. Supported output formats are `html`, `json`, `yaml`, `csv`, and `rss`; HTML is the default when no explicit `format` or acceptable content type selects another format. Standard format availability is operator-configurable. Explicit unknown formats return HTTP 400 `unsupported_format`; configured-off standard formats return 403 `format_disabled`. Framework-level search validation is normalized to a format-aware HTTP 400 (`invalid_filter` or `invalid_request`), while non-search framework validation remains 422. Engine failures normally produce partial results and appear in `unresponsive_engines`; they do not turn a partially successful query into an all-or-nothing error. Preserve exact JSON fields, YAML+Markdown document shape, CSV columns/escaping, RSS item semantics, content types, statuses, and HTML security headers through `tests/test_formatter.py`, `tests/test_server.py`, `tests/test_searxng_api_contract.py`, and `tests/test_portal_browser.py` (owners T02/T03).

`GET /health` is cheap liveness plus Valkey connectivity and observed engine health; it does not probe upstream search services. Never-observed engines are `unknown`, not healthy. If config/catalog lookup fails it degrades to a minimal health response instead of failing the probe. `GET /healthz` is the SearXNG-compatible plain-text `OK` readiness response. `GET /metrics` emits OpenMetrics text with version `0.0.4`. `GET /config` returns SearXNG-compatible top-level config plus additive engine/capability metadata; it must remain useful if catalog generation fails. Tests: `tests/test_server.py`, `tests/test_observed_health.py`, `tests/test_metrics.py`, `tests/test_service_engine_config.py` (T02, O01/F06 as listed in the manifest).

The browser search portal is the HTML representation of `/` and `/search`, not a separately authenticated public API. Public search must not require a browser session or depend on cookie presence. It carries query/category/engine/language/time-range/safesearch/page state, capability-aware choices, warnings, filter enforcement, result groups, suggestions and ranking explanations. Security response headers include CSP, no-referrer, nosniff, and restrictive Permissions-Policy. Grouping failure is rendered as unavailable while search still succeeds. See `tests/test_portal_browser.py` and formatter/server tests (T03).

The workflow console is a separate protected router mounted in the same ASGI application. `/auth/login` and `/auth/callback` implement OIDC; `/auth/tenant` GET selects/reads tenant state and POST changes it; `/auth/logout` revokes the browser session. `/workflows` and `/workflows/{kind}/{object_id}` render tenant-authorized objects; POST `/workflows/{kind}/{object_id}/{action}` performs the supported workflow action. Mutations require an authenticated principal, active tenant membership, same-origin checks, CSRF validation and the action-specific expected revision/idempotency inputs; event cursors and questions/strategies are validated per action. Preserve deny behavior, redirects, cookies, tenant isolation and audit events. Owners T09/W10; mandatory tests are route-specific `tests/test_workflow_portal.py`, `tests/test_portal_oidc.py`, `tests/test_portal_auth.py`, and `tests/test_portal_audit.py` as enumerated by route in the manifest. Browser auth must not leak into the public search routes.

## MCP wire surface

`create_server()` registers exactly the 38 ordered entries in `TOOL_DEFINITIONS`, four resource registrations (three fixed URIs plus the engine URI template), and five prompts. `surfaces.json` lists every callable, grant, durable/snapshot requirement, mutability, policy-gate flag, source module, contract test and migration owner. Tool schemas are part of the public contract: preserve required/optional arguments, JSON-schema types/defaults, descriptions, structured result envelopes, errors and null/empty distinctions. `tests/test_mcp_tool_registry.py` checks registry completeness and ordering. Each tool's listed `transport_test` is mandatory, together with `tests/test_mcp_harness.py`; workflows additionally require their feature-specific transport suites.

Tools that dispatch or revalidate a stored engine scope must preserve the shared fail-closed sensitive-engine policy. Specialist grants enable named tool families but do not grant access to sensitive engines; mixed sensitive and non-sensitive explicit scopes reject atomically. Research, saved-search, staged-search, receipt, and dossier tools have durable state and preserve their declared mutation/idempotency semantics. Snapshot readers must distinguish missing/expired IDs from valid empty results and keep tenant-bound access. A tool error is not a successful empty object. Read-only catalog/status tools and planning calls retain their non-dispatch behavior.

Resources are text: `slopsearx://capabilities`, `slopsearx://routing-profiles`, and `slopsearx://health/summary` are fixed; `slopsearx://capabilities/{engine}` is the one URI template. Before MCP initialization, resource renderers return the explicit “server is not initialized” text; an unknown engine returns a useful valid-name response. Credential material is redacted. Health is observed/stale/unknown state, not an active provider probe. Prompts and their argument names are enumerated in the manifest; prompts are caller-workflow templates and must retain the warning that snippets/findings are not verified page bodies.

Supported runtime transport modes are stdio (default), streamable HTTP (`http` and `streamable-http` aliases), and legacy SSE (`sse`). At the locked FastMCP 4.0.11 / MCP 2.3.0 baseline, SSE uses `GET` and implicit `HEAD /sse` for the `text/event-stream` connection. Its POST-oriented message handler is configured with advertised prefix `/messages/`; Starlette normalizes the actual mount route path to `/messages`, where the mount accepts an arbitrary suffix for session message requests. The handler does not declare an explicit method allowlist. Paths default from SDK settings and can be overridden with `FASTMCP_SSE_PATH` and `FASTMCP_MESSAGE_PATH`. The exact route objects were inspected in the local locked environment without starting lifespan or calling providers. Default `mount_path` is `/`. The current CLI SSE branch calls `create_server()` without static bearer or OAuth configuration, so these endpoints are unauthenticated. The message handler requires `session_id` and valid JSON-RPC (400 for missing/invalid input, 404 for unknown session, 202 when accepted). The baseline has no SSE-specific tests; T01/T06 must add them. The remote gateway is a local stdio MCP server that dynamically proxies the remote server's complete paginated tool/resource/prompt catalogs over streamable HTTP; preserve remote schemas and error precedence, including empty structured results and remote errors. HTTP static bearer mode requires `Authorization: Bearer …` on every HTTP request when configured; comparison is constant-time and unauthorized requests return 401. With no token and no OAuth, HTTP currently warns and runs unauthenticated. OAuth server mode owns protected resource/authorization endpoints and replaces static-token mode. Stdio is trusted at process launch. Owner T01 qualifies exact SDK transports and schema; T05/T06 implement server and tool surface; T07 ports gateway/client; tests include `tests/test_mcp_security.py`, `tests/test_mcp_oauth.py`, `tests/test_mcp_oauth_client.py`, `tests/test_mcp_gateway.py`, `tests/test_mcp_gateway_lifecycle.py`, and `tests/test_mcp_harness.py`.

## Native command and deployment entrypoints to replace

The Python CLI entrypoint is `slopsearx-mcp` (`python -m slopsearx.mcp` is its module alias). Without `--remote`, it runs local stdio by default or serves HTTP/SSE according to `--transport`/`MCP_TRANSPORT`; host/port come from `MCP_HOST`/`MCP_PORT` (defaults 127.0.0.1:8000). Invalid port falls back to 8000; unknown transport warns and falls back to stdio. `--remote` selects a stdio gateway; `--token` and `--oauth` are mutually exclusive. OAuth supports callback port (8765 default), no-browser mode and a token file. `MCP_REMOTE_URL`, `MCP_REMOTE_TOKEN`, `MCP_REMOTE_OAUTH`, `MCP_REMOTE_OAUTH_CALLBACK_PORT`, `MCP_REMOTE_OAUTH_NO_BROWSER`, and `MCP_REMOTE_TOKEN_FILE` are flag defaults. MCP transport/schema/lifecycle qualification belongs to T01; server transport and registered-tool surface belong to T06; gateway commands belong to T07. T08 owns only the separate `ssx` client. See gateway/OAuth tests in the manifest.

The server container currently launches `uvicorn slopsearx.server:app --host 0.0.0.0 --port 8080`; its Docker healthcheck runs `python /app/healthcheck.py`. Compose has a digest-pinned production service and an optional `build` profile service; deploy exactly one variant because they share the network alias. The source-build path requires a fresh `DEBIAN_SECURITY_REFRESH` build argument. Operational commands include `docker compose build`, `docker compose up -d`, `docker compose down`, `docker compose restart valkey`, and the runbook's full build/down/up sequence. Kubernetes deployment is defined in `k8s/deployment.yaml`; preserve digest pinning, probes, resource/security settings and rollout/rollback procedures. Release and digest-promotion tools include `.github/workflows/docker.yml`, `.github/workflows/image-promotion.yml`, `scripts/promote_image_digest.py`, and `scripts/verify_docker_base_digest.py`; do not treat CI-owned hosted service internals as backend code, but replace project-owned Python invocation/build requirements. Owners O02/O04/O06/O09 and G05–G09. Tests include `tests/test_deployment_artifacts.py` and release-artifact checks.

`ssx` is a standalone HTTP client with `search`, `engines`, `health`, and `config` subcommands; it uses `SSX_URL` (default `http://localhost:8080`), `SSX_FORMAT` (YAML unless `json`), 15-second HTTP timeout, and `--json` override. Search takes one-or-more query tokens, categories, engines, language (default `en`), time-range and page (default 1). It reads `/search`, `/health`, and `/config`, and reports connection/query errors to stderr with exit 1. T08 owns native replacement. No CLI-specific test file exists at the pinned baseline; T08 must add native CLI tests for help, query construction, YAML/JSON selection, HTTP failures and exit codes.

## Wire-value details that affect compatibility

For successful JSON, `query` and `results` always exist; each result includes the full SearXNG field set. Missing optional scalar data is serialized as JSON `null` (`publishedDate`, `pubdate`, `thumbnail`, `img_src`, `media`, `payload`, `parsed_url`, and currently unsupported SearXNG slots such as `author`/`views`), whereas `answers`, `corrections`, `infoboxes`, `suggestions`, and `unresponsive_engines` are always arrays and use `[]` when empty. `engines` is omitted unless engine status metadata is present. Top-level `meta` is omitted when absent. Empty or malformed result URLs yield `parsed_url: null`; no position yields `positions: []`; empty engine provenance falls back to `[engine]`. Payloads are included only when canonical serialization is possible and fits both the inline and persistence byte bounds; otherwise the payload field is `null`, not a truncated payload. CSV emits its header even for zero results and uses an empty publication-date cell. RSS emits an empty channel and omits `pubDate` when the date is absent. YAML+Markdown preserves its YAML header and embedded markdown boundary; optional meta subfields are populated according to the formatter contract.

A bare `GET /` with no nonblank query and HTML negotiation returns the landing page. The same path with a machine format, every `/search` request without a query, or a blank query returns 400 `query_required`; do not collapse the human landing-page case into API validation. POST query parameters are read first and URL-encoded form fields overlay them (last repeated form value wins); unsupported body content types do not become form fields. Invalid page (<1), safesearch outside 0/1/2, and interactive timeout outside 1..30000 return format-aware 400 errors. A rate-limit rejection is 429 `rate_limited`; explicit sensitive-engine selection without grant is 403 `engine_restricted` before dispatch. These wire distinctions are exercised through `tests/test_server.py` and `tests/test_formatter.py`.
