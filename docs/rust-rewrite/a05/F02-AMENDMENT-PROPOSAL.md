## Decision proposed for review

Introduce a backend-only native HTML compatibility component and a supervised native parser helper. Keep the HTTPX-compatible decoder in safe native Rust, with generated data from immutable source observations. The application continues to call one adapter search interface. No Python interpreter/API/subprocess/service is permitted in runtime or mandatory gates. A05 remains incomplete until all current186 captures and broader codec/parser evidence execute through this architecture.

Library source selection and binding selection are separate decisions. Qualify both oracle libxml2 2.14.6 and maintained candidate2.15.4 offline; ship2.15.4 only if complete source comparison and security review close. Do not adopt the currently inspected libxml wrapper unchanged: it has no safe context resource-loader API, and its build assumes features not present in a minimal C configuration.

## Binding and safety boundary

Inspected libxml0.3.22 provides safe Parser::parse_string_with_diagnostics and owned diagnostics, privately owns/free its xmlParserCtxt, and caps collected diagnostics100. Its Document/Node graph uses Rc/RefCell; confine all C objects inside one helper's single-threaded parse job and return only owned typed values. Do not expose raw pointer constructors, mutable tree handles or XPath strings to adapter callers. Do not use read-only node Send/Sync assumptions as an ownership escape.

Its ParserOptions no_net defaultsfalse; setting ittrue is insufficient because current libxml2 NONET has no effect. It exposes no safe resource-loader policy; safe diagnostics parsing creates its private context immediately before htmlCtxtReadMemory. Therefore upstream0.3.22 unchanged cannot satisfy deny-all external-resource acceptance. It also sets LIBXML_C14N_ENABLED and LIBXML_OUTPUT_ENABLED in bindgen and exposes schema/save APIs. Disabling those C symbols without resolving Rust references risks link failure or ABI misconfiguration.

Proposed resolution: a reviewed upstream binding extension, or a narrowly patched vendored copy retaining exact upstream package checksum and an independently hashed patch. Add one safe parse entry point that always installs a context-local denying resource loader and fixes encoding/options; it accepts bytes and returns an owned document/error only. Callback returns an explicit resource-load denial without opening URLs, files, catalogues or arbitrary schemes. No caller-supplied callback or raw pointer API is exposed by our facade. Review callback ABI, lifetime, panic behavior, null handling, context/document destruction, error-handler restoration and process initialization. Keep workspace unsafe_code=forbid unchanged: any FFI patch is an explicitly reviewed dependency-internal patch, not a workspace lint exemption. Parent must approve the exact patch/hash before adoption; this draft does not contain or approve such a patch.

An alternative minimal maintained safe binding is acceptable only with equivalent audited API/ABI and package evidence. A handwritten workspace FFI boundary is not currently proposed or authorized. If no suitable binding can be qualified, report the unresolved architecture gap rather than bypassing unsafe forbid.

Cargo must never download C sources or discover a system libxml2. ## Helper lifecycle and security contract

Prefer one separately packaged Rust helper binary, ssx-html-parser, with a fixed versioned framing protocol over inherited pipes. It imports only codec/parser/model components, no HTTP client, Valkey, credentials or configuration. Backend spawns a bounded pool at startup before accepting provider work. Concurrency is configurable and bounded (four workers is a starting tuning value, not a public capacity contract); wait remains owned by the existing deadline, with no new timeout. Reserve a worker before decoding so queued searches do not retain extra decoded copies. F08 already admits32MiB decoded bytes: helper input ceilings must be derived from that accepted byte bound and each applicable codec maximum UTF8 expansion, including escaped/name codecs. Output ceilings must derive from result limits and bounded extracted fields; no unexplained16MiB restriction is accepted. Derive and measure these bounds before runtime integration, rejecting overflow explicitly; diagnostics remain capped100. This draft proposes no new source-incompatible admission limit. Request deadline is the existing adapter deadline, never extended for parsing. Saturation waits only within that deadline/cancellation token.

Per helper job: reserve slot→write bounded frame with request ID/deadline→parse/extract whole owned result→write bounded response→backend validates frame/type/ID→release. On deadline, cancellation, malformed output, crash or oversize: close input, kill helper, await OS child reaping, then release slot and spawn replacement only if backend is still running. No detached Child/JoinHandle; use explicit kill+wait, not kill_on_drop as proof. EOF/shutdown stops admission and kills/reaps all active/idle helpers. Reject descendants: helper launches none and receives no arbitrary executable path. Treat failed replacement as readiness failure rather than unbounded respawn. Generation/job IDs prevent stale responses being attached to a new search.

Process isolation does not itself deny file/network reads. Defense1 is mandatory denying resource loader plus disabled features and closed extension APIs. Defense2 for Linux deployment is a dedicated helper confinement policy: no network namespace egress, empty read-only runtime root containing executable/required system runtime only, no credentials/config/provider files, no inherited extra FDs, non-root, no_new_privs, no descendant process creation, memory/address-space and CPU cap. Native macOS developer execution must not claim Linux sandbox properties; loader refusal and lifecycle tests still run there. OS sandbox mechanisms/values need an implementation-specific review. Consider a parent launcher/container profile rather than unreviewed unsafe Rust pre_exec code. Until confinement is proven, hard resource-isolation qualification is pending.

Test kill/reap with deliberately blocked native helper fixtures, controlled clock deadlines, cancellation before write/during parse/during output, output flood, crash, frame spoof/partial frame, pool saturation, failed respawn and server SIGTERM. Assert child PID no longer exists, wait status observed, slots reclaimed only after wait, no descendants, bounded pending/output bytes and successful next job. Test external entities/DTD/file://,HTTP(S),FTP,relative paths,catalogue/PUBLIC identifiers and XPath attempts against a canary file and loopback listener: zero reads/connections, denial observed, source error differences explicitly adjudicated. No provider traffic.

## Native decoder implementation sequence

Measured inventory455 labels/117 canonical includes108 applicable text decoders; nine known-but-rejected paths differ from unknown-label UTF8 fallback and empty-body short circuit. Keep native decoder API Result<String,SourceDecodeError>; preserve error stage/classification, exact source/native diagnostic contract and BOM/replacement semantics. Do not flatten errors into a successful lossy UTF8 decode.

Separate data/provenance generation from runtime. Generate aliases69 single-byte tables and Unicode-name data only after immutable source/licensing review; implement3 simple codecs,9 Unicode algorithms,24 multibyte/stateful contracts and3 Python algorithms in safe Rust. Reuse encoding_rs only for families with complete differential evidence. Compare full valid/invalid/truncated/streaming sequences per family and every alias, including empty/rejected codecs. Frozen source-codec-policy.json is evidence, not an executable Python backend or permission to silently restrict the codec set. Decoder work may proceed independently after its mapping/algorithm provenance is reviewed; no partial family completion establishes full HTTPX parity.
