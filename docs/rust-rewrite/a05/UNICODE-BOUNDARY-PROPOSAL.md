# A05 codepoint/helper boundary proposal

Actual observations:44 whole-engine captures, four codecs (UTF7, raw_unicode_escape,unicode_escape,punycode) ×11 isolated/embedded cases in surrogate-pipeline-observations.json. Original decoded codepoints, final field codepoints, raw status/headers/bytes, requests, config and complete normalized outcomes retained. Original186corpus bytes unchanged. These44new observations are not yet mandatory native replay and must become so before acceptance.

Isolated high/low surrogate: all four codecs yield source lxml ParserError Document is empty. Embedded high/low in `<h3>A...B</h3>` does **not** reject the whole document or replace with UFFFD: source preserves title A, drops the rest of parse including subsequent snippet, and returns OK. In an href the source loses the candidate link/result; in image alt it preserves the link but falls back to query title. Global rejection or replacement is therefore incorrect.

Valid UTF7 surrogate pair decodes immediately to U10000. Raw/unicode_escape and punycode retain two source codepoints D800,DC00, which lxml's UTF16 input then combines to U10000. Presence of an unrelated astral character forces Python's full string to PEP393kind4; preserving the raw input sequence and representation choice is required. JSON escaping alone cannot distinguish a genuine scalar from two retained surrogate codepoints, so captures include explicit codepoint arrays.

Source parser.pxi _parseUnicodeDoc (1074–1140) consults actual PyUnicode_KIND and PyUnicode_MAX_CHAR_VALUE storage capacity, not a direct max(codepoints) calculation. CPython3.14.7 Include/cpython/unicodeobject.h:124–145 requires minimal kind for completed strings; Objects/unicodeobject.c:747–762 enforces the corresponding maximum-codepoint lower/upper bounds under content consistency checking. Native max-codepoint reconstruction therefore selects the same representation for these completed valid source strings: ASCII→UTF8bytes,Latin1→ISO8859-1bytes,BMP(including surrogate units)→native-endian UTF16 units,larger→native-endian UTF32 units. It passes the whole source length to libxml2 with explicit encoding. HTML default options are RECOVER|NONET|COMPACT (no HUGE). _parseMemoryDocument refuses the exact XMLencoding regex before that boundary. These are source observations, not normalization proposals.

Propose an adapter-local native decoded Text represented as Vec<u32> (or reuse A04's accepted adapter-owned Text codepoint primitive when available). Keep global ssx_json unchanged. Valid scalar-only paths can cheaply borrow UTF8, but do not erase the distinction for surrogate-bearing data. ASCII challenge/validempty marker scans may operate over codepoints, preserving every other value; no lossy conversion or globalsurrogate rejection. The existing safe helper API &str is insufficient for all108codec paths.

Extend the reviewed dependency-safe API to accept validated codepoints≤10FFFF and construct the same PEP393kind/encoding byte buffer. This uses the existing private context/refusal/error guard and adds no rawpointer/callback/options inputs. Invalid out-of-range protocol values fail as native protocol errors; source codec errors remain their original errors. Send codepoint count+fixed-width native-independent u32 values over boundedIPC; do not round-trip through a standard RustString/SerdeValue. Bound count from accepted32MiBF08bytes and a complete per-family codepoint expansion derivation (still required; measured examples alone are insufficient). Helper chooses the encoding from maximum codepoint, validates frame, invokes libxml2 and returns owned valid extracted strings/tree. The observed lxml handling of malformed UTF16/32 must be reproduced by actual candidate qualification, not by preemptive surrogate replacement.

This remains a proposal for parent review. Current vendored API still uses &str; no surrogate narrowing is accepted. Full wrapper and every new capture must execute before parity claims; latest2.15.4NUL behavior also needs explicit2.14.6comparison, rather than an unrelated surrogate correction.
