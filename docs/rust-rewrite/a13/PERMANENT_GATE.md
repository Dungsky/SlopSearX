# Permanent A13 native qualification gate

`cargo xtask check A13 --output target/rust-evidence/A13.json` is the proposed permanent gate. It builds all workspace targets before helpers can be used, checks five complete compiled inventories (214 infra library, 16 JSON library, 21 DeHashed, 20 HIBP, 22 IntelX), then executes all 75 exact selectors with their original capture flags. The inventories are source-derived and compiler-unproven in this proposal. The gate does not reuse any prefix of the private 95-command qualification.

The typed qualification envelope binds current runtime, native fixture, static original-text, C/Unicode asset and documentation bytes separately from the pinned historical static maps. Existing original maps/producer hashes and their source baselines remain unchanged. Each selector has its exact current source file, SHA and function line. The three Python engine implementations and original tests are read as text only; no Python interpreter or provider is invoked. No manual historical producer is promoted to CI.

The gate requires exact whole-line libtest grammar, one named successful nonignored completion per selector, source-owned split payloads only, and the complete 128 parent marker identities (76+3 DeHashed and 42+7 remaining). All three literal HTTP parent selectors retain canonical Base64 child stdout/stderr and explicit successful exit, both joined EOFs, no forced kill, exact byte lengths and unchanged 1 MiB bound. Decoded child stdout must independently contain exactly its own harness identity and child completion; the HIBP/IntelX nested case marker is scoped separately from the parent. Exit/EOF evidence is not an operating-system process-family absence claim.

Five proposed Rust negative-control tests cover wrong/extra/duplicate/ignored harness identities, unknown split payloads and junk marker prefixes, canonical Base64 bits/padding, duplicate raw records, child status/EOF/length/engine/nested identity corruption, and compiled list corruption. They must themselves execute successfully through the gate; their source presence is not qualification.

Both existing Linux foundation matrix entries invoke A13 and upload its source-bound JSON report, including full native command output and lossless child Base64. All other gate steps and artifacts are retained. The existing source identity framework guards current Git blobs before/after the gate. Current main integration, exact-head Linux CI, substantive review, portal impact, production composition, global memory/RSS and remaining migration work remain separate acceptance obligations. No backend Python fallback, stage disabling or provider calls are introduced.

Status: SOURCE-ONLY PROPOSED PERMANENT GATE; not applied, formatted, compiled or executed. Prior private component observations retain their original identities/failures and do not establish this new gate passes.
