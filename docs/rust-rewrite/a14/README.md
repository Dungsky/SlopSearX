# A14 ATS jobs adapters

Issue [#933](https://github.com/magnus919/SlopSearX/issues/933) ports Ashby,
Greenhouse, Lever, and company-name extraction. Root accepted the corrected
native component after independent source review and actual qualification:
18 test functions, 178 distinct completed controls, and two gate guard tests
passed. Current-main integration and hosted CI remain required before delivery.
The prior eight-function result belongs to the archived earlier candidate.
`cases.json` pins the original Python sources, exact native test functions,
individual completed controls, accepted helper blobs, and reviewed jobs source.

The adapters use the accepted F08 HTTP session and the existing registry.
`JobsConfig::from_resolved` retains F06 raw scalar variants through actual
registry factories. Boolean and signed integer result limits follow Python
slicing; float and string limits fail at the source slice operation, after
HTTP/status/JSON and Lever's outer-list check. Timeout arithmetic preserves
raw kinds and fractional values. Extreme numeric timeouts follow the accepted
A09 finite caller-lifecycle behavior (`clinicaltrials::network_deadline`);
without a representable configured deadline or finite caller deadline the
native lifecycle refuses an unbounded exchange. String timeouts fail arithmetic.

Provider JSON bytes use the accepted `source_json` decoder, including
UTF-8/16/32 BOM/autodetection, nonfinite numbers, and escaped surrogates.
Source values remain intact through every row's slicing, iteration, f-string
IDs and string joins. Unused incompatible values do not cause output refusal.
Only after all source operations succeed does the adapter project retained
fields through the F05 boundary; a real source error in a later row discards
all results and wins over an earlier pending typed-output refusal. Greenhouse
payloads use the accepted cooperative, budgeted payload envelope and batch
assembler, including surrogate sanitation of retained payload data.

Company extraction retains the approved Unicode 16 proof: all 1,112,064 scalar
values are checked for lowercase output length and each position's ASCII versus
non-ASCII projection, with pinned UnicodeData/SpecialCasing and Final_Sigma
context controls. No new Unicode implementation or casefold behavior is added.

Lever timestamps divide milliseconds by 1000 before applying CPython's
fractional-second, half-even microsecond rounding and carry normalization.
`cases.json` records the pinned CPython C-file hashes and static proof. The
expected timestamp controls are source-derived; they are not Python oracle
observations. Native controls include positive/negative half-microsecond ties,
negative fractions, fractional carry, precision loss at modern epochs, and
both ends of Python's datetime year range.

The native suite includes exact original inline provider bodies, every
source-asserted result/payload field, configured double-slash URL paths, the
exact Ashby GraphQL document, all three providers' timeout/drop/owner-shutdown
and parse-deadline controls, raw F06 settings, and whole-response error
precedence. No provider, backend, oracle, or external service is executed.

`cargo xtask check A14` verifies the pinned map and source,
exact test pass identities/counts, and each completed control identity once.
It hashes the entire Rust/vendor/Cargo/A14 source inventory before and after
the run. Missing, ignored, skipped, duplicate, failed, or extra controls fail
closed. The native command uses `--show-output --test-threads=1` so both test
identities and completed controls are retained. Logs and whole-source archives
remain under the owned A14 evidence directory on tank.

Shared topic routing, registry metadata aggregates, policy/enforcement, portal
and cross-tool result integration remain with their established owner gates.
No browser-visible contract change is intended; the port preserves jobs fields,
category, tier, dates, payload provenance and result behavior. `cases.json`
retains the higher-level source-test traces; root owns aggregate acceptance.
